llm-gateway 部署完成（namespace: {{ $ns }}）

组成：
  PostgreSQL  svc/llm-gateway-postgresql :5432（虚拟 key / 记账存储）
  LiteLLM     :4000（服务名以 kubectl get svc 输出为准）

1) 等待就绪（postgres 先起，litellm 随后）
   kubectl -n {{ $ns }} get pods -w

2) 找到网关 Service 并转发
   SVC=$(kubectl -n {{ $ns }} get svc -o name | grep -i litellm | cut -d/ -f2)
   kubectl -n {{ $ns }} port-forward svc/$SVC 4000:4000

3) 路由表（应列出 qwen-7b-int4 / qwen-1.5b 两个虚拟模型名）
   curl -s localhost:4000/v1/models -H 'Authorization: Bearer sk-litellm-master-m4lab'

4) 路由到两个后端
   curl -s localhost:4000/v1/chat/completions \
     -H 'Authorization: Bearer sk-litellm-master-m4lab' -H 'Content-Type: application/json' \
     -d '{"model":"qwen-7b-int4","messages":[{"role":"user","content":"ping"}],"max_tokens":8}'
   （改 model 为 qwen-1.5b 打到 vllm-smoke）

5) 虚拟 key + 配额（依赖 DB；超 tpm_limit 后应 429）
   curl -s -X POST localhost:4000/key/generate \
     -H 'Authorization: Bearer sk-litellm-master-m4lab' -H 'Content-Type: application/json' \
     -d '{"key_alias":"team-canary","max_budget":1,"tpm_limit":100}'

排障速查：
  404 model not found   → 后端 --served-model-name 与 model_list 不一致，curl 后端 /v1/models 核对
  401 认证失败          → kubectl -n {{ $ns }} get secret litellm-masterkey -o yaml 核对 masterkey
  DB 连接报错           → kubectl -n {{ $ns }} logs <litellm pod>；核对 db.endpoint 与 db.secret
  依赖拉取失败          → helm show chart oci://ghcr.io/berriai/litellm-helm（OCI name/版本核对）
  子 chart 版本回放     → cat Chart.lock（精确版本记录在此）
